## 2. Task 1: Fix Production Fallback (`authQueries.js`)

### Vulnerability Remediated:
Previously, if a database timeout occurred during cold start, `checkDbAuthColumns()` caught the error and set `dbHasAuthColumns = false`. This permanently cached `false`, causing all subsequent production registrations to silently store credentials in volatile RAM (`authCredentialStore`), which vanished upon container restart.

### Code Implementation Applied:

```javascript
import { pool } from '../config/db.js';
import { env } from '../config/env.js';
import { DatabaseError } from '../errors/DatabaseError.js';

let dbHasAuthColumns = null;

export function resetDbAuthColumnsCache() {
  dbHasAuthColumns = null;
}

export async function checkDbAuthColumns() {
  if (dbHasAuthColumns !== null) return dbHasAuthColumns;
  try {
    const res = await pool.query(`
      SELECT column_name 
      FROM information_schema.columns 
      WHERE table_name = 'users' AND column_name = 'password_hash'
    `);
    const hasColumns = res.rows.length > 0;
    if (env.NODE_ENV === 'production' && !hasColumns) {
      throw new DatabaseError(
        'Database authentication schema is missing in production. Migration 002 must be applied to persist credentials.'
      );
    }
    dbHasAuthColumns = hasColumns;
    return dbHasAuthColumns;
  } catch (err) {
    if (env.NODE_ENV === 'production') {
      throw err instanceof DatabaseError
        ? err
        : new DatabaseError(`Failed to introspect database authentication schema: ${err.message}`, err);
    }
    // In development / test, do not permanently cache false on query error so retries can succeed
    return false;
  }
}
```

### Additional Fallback Guards Implemented:
1. **Fallback Operation Blocking:** In all 7 authentication query functions (`findUserByEmail`, `findUserById`, `findUserByActivationHash`, `insertCandidate`, `updateUserPassword`, `assignActivationToken`, `insertCounselor`), if `!hasColumns` and `env.NODE_ENV === 'production'`, the function immediately throws `DatabaseError('In-memory authentication fallback is strictly prohibited in production.')`.
2. **`AuthCredentialStore` Class Guard:** Inside `initUser`, `registerCandidate`, `provisionCounselor`, `setActivationToken`, and `activatePassword`, any invocation while `env.NODE_ENV === 'production'` immediately throws `DatabaseError('AuthCredentialStore cannot be accessed in production environment.')`.
3. **Cache Invalidation:** In development/test mode, transient query errors no longer lock `dbHasAuthColumns` to `false` permanently; subsequent requests retry the query until PostgreSQL is reachable.

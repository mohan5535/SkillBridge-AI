  <action>
    Create Zod validation schemas in `src/validators/authSchemas.js`:
    - `registerSchema`: validates `email` format, `full_name` (min 1, max 100), `password` (min 8 chars, 1 uppercase, 1 lowercase, 1 number, 1 special symbol, and `Buffer.byteLength <= 72`), and `country`. Use `.strict()` to reject any payload containing `role`, `user_type`, `is_admin`, or `permissions` per AUTH-01.
    - `loginSchema`: validates `email` and `password` (max 72 bytes).
    - `activateAccountSchema`: validates `token` (64-character hex string) and `password` (same complexity & 72-byte limit).

    Create SQL query constants in `src/queries/authQueries.js`:
    - `REGISTER_CANDIDATE`: inserts into `users (email, full_name, country, password_hash, role)` explicitly hardcoding `'candidate'` as the role parameter `$5`.
    - `GET_USER_BY_EMAIL`: selects `user_id, email, full_name, role, password_hash, activation_token_hash, activation_token_expires_at` by email.
    - `GET_USER_BY_ACTIVATION_HASH`: selects user where `activation_token_hash = $1 AND activation_token_expires_at > CURRENT_TIMESTAMP AND password_hash IS NULL`.
    - `ACTIVATE_USER_PASSWORD`: updates `users SET password_hash = $1, activation_token_hash = NULL, activation_token_expires_at = NULL, updated_at = CURRENT_TIMESTAMP WHERE user_id = $2`.

    Implement `register` method in `src/controllers/auth.controller.js`: validates body against `registerSchema`, hashes password with bcrypt cost 12, inserts candidate with forced role 'candidate', sets `sb_auth_token` and `sb_csrf_token` cookies, and returns JSend HTTP 201 Created with sanitized user details.

    Author integration test `tests/integration/authRegistration.test.js` verifying:
    1. Valid registration creates candidate and returns HTTP 201 with sanitized user payload (no password_hash).
    2. Submitting duplicate email returns HTTP 409 Conflict.
    3. Submitting payload with `role: 'counselor'` or `role: 'admin'` is rejected with HTTP 400 Bad Request or strictly forced to 'candidate'.
    4. Mutations execute within withTransaction and are rolled back to preserve 174 baseline rows.
  </action>

  <action>
    Implement `activateAccount` method in `src/controllers/auth.controller.js` per AUTH-03:
    - Rejects password setup attempts using email alone without a token with HTTP 400 Bad Request.
    - Validates payload against `activateAccountSchema`.
    - Computes SHA-256 hash of submitted raw token: `crypto.createHash('sha256').update(req.body.token).digest('hex')`.
    - Queries database using `GET_USER_BY_ACTIVATION_HASH` checking that `activation_token_expires_at > CURRENT_TIMESTAMP` and `password_hash IS NULL`.
    - If no matching row is returned, throws ValidationError with HTTP 400 Bad Request (`code: 'INVALID_ACTIVATION_TOKEN'`, "Activation token is invalid, expired, or has already been used.").
    - Hashes new password via `authService.hashPassword(password)` (bcrypt cost 12).
    - Executes `ACTIVATE_USER_PASSWORD` inside `withTransaction`, setting `password_hash`, clearing `activation_token_hash` to NULL, and clearing `activation_token_expires_at` to NULL in one atomic statement to permanently prevent token replay.
    - Issues `sb_auth_token` HTTP-only cookie and sets `sb_csrf_token` cookie.
    - Returns JSend HTTP 200 OK with sanitized user profile.

    Create `src/routes/auth.routes.js` mounting:
    - `POST /register` -> `authController.register`
    - `POST /activate-account` -> `authController.activateAccount`

    Author integration test `tests/integration/authActivation.test.js` verifying:
    1. Valid single-use token successfully activates account and sets password.

    3. Submitting an expired token is rejected with HTTP 400.
    4. Attempting to activate an account that already has a password_hash set is rejected.
    5. Attempting to activate with email alone without token is rejected with HTTP 400.
